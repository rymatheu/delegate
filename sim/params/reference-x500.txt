# Motors: the plant. The harness maps PWM 1000..2000 linearly to the actuator a in [0, 1] and a to the propeller speed
# MAX_RPM sqrt(a) (run_copter.actuators_to_rpm, as leanfc's run_leanfc.py), so the thrust of a motor is a x 8.54858 N:
# linear in the actuator from zero, i.e. thrust curve exponent 0 and spin range [0, 1]. The motor lag (12.5 ms up, 25 ms
# down) is the simulator's.
MOT_PWM_MIN 1000       # (default 1000; stated)
MOT_PWM_MAX 2000       # (default 2000; stated)
MOT_THST_EXPO 0        # default 0.65: the plant's thrust is linear in the actuator
MOT_SPIN_ARM 0         # default 0.10: actuator 0 is zero thrust in the plant (no ESC dead band to idle above)
MOT_SPIN_MIN 0         # default 0.15: idem; spin_min > 0 would add spin_min x 8.55 N per motor that ArduPilot does not expect
MOT_SPIN_MAX 1         # default 0.95: actuator 1 is the model's maximum thrust (1000 rad/s)
MOT_HOVER_LEARN 0      # default 2 (learn and save): the hover throttle below is exact for this plant
# Hover: thrust fraction 1/thrust2weight = 1/1.689113625 = 0.59203. At the gorge (4302 m, field elevation set from the EKF
# origin) ArduPilot's air-density compensation (AP_Motors_Thrust_Linearization::get_compensation_gain) divides every
# motor demand by the 1976-atmosphere density ratio 0.64783, while the simulated thrust does not depend on altitude; the
# throttle demand that hovers this plant there is 0.59203 x 0.64783 = 0.38353 (what MOT_HOVER_LEARN would converge to).
MOT_THST_HOVER 0.3835

# Yaw, changed from the file for this model (gorge flights sim/out/gorge-port-x500/try1..try5): with the file's yaw values
# the yaw loop limit-cycled at about 1.5 Hz with motors at 0 and 1 (try1: contact with the terrain at N 31.7 m). The
# model's yaw authority is small: momentConstant 0.016 m, so a unit yaw output gives 4 x 0.5 x 8.55 N x 0.016 m / 0.04 kg m^2
# = 6.8 rad/s^2, times 1.544 at 4302 m (the density compensation), and at the hover actuator 0.592 a motor has only 0.41 of
# headroom, about 5.5 rad/s^2 of yaw acceleration in all; the file asks for 359.55 deg/s^2 = 6.3 rad/s^2. So: the yaw
# acceleration limit at 90 deg/s^2 (try2: the mission completes, yaw still cycling); the yaw rate P, I, D times the density
# ratio 0.648, which cancels the compensation's gain (try3); the yaw error filter at ArduPilot's default 2.5 Hz and the
# yaw angle P at 3 (default 4.5, file 8.5), so that the angle loop stays well inside the rate loop (try4, try5). Roll and
# pitch keep the file's gains: their loops are quiet (actuator std from roll and pitch below 0.001 in cruise).
