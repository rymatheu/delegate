# Theory critique of docs/delegation-algorithm.tex

Reviewer's stance: hostile but fair. Every claim was re-derived by hand; the set-level claims were also checked in Lean (notes/validation/Deleg.lean, Section 3 below). Verdicts: CONFIRMED (correct as written, possibly with a cosmetic remark), GAP (correct only under an assumption the write-up does not state, or the argument is incomplete), WRONG (false as stated). Each finding ends with a fix.

## 0. Symbols

Ports: U (planner input, static), W (mission, static, N item slots plus a length field n), E = E_s ∪ E_d (environment: static part E_s, per-tick part E_d), Y (per-tick targets). Pi := U ∪ W ∪ E ∪ Y. Ticks t ∈ {0,…,H}. Omega is the set of behaviours: maps giving each static port one value and each per-tick port one value per tick. For a set S ⊆ Omega, ¬S := Omega ∖ S. For X ⊆ Pi, two behaviours are X-equivalent if they agree on every port outside X; ∃_X S is the set of behaviours X-equivalent to a member of S, and ∀_X S := ¬∃_X¬S. S is over Z ⊆ Pi if ∃_{Pi∖Z} S = S. Contract (A, G) is a pair of sets; M ⊨ (A, G) iff M ∩ A ⊆ G. The given data are A (over U ∪ E), G (over U ∪ E ∪ Y), the controller M2 (over W ∪ E ∪ Y) and, from steps 1–2, V (over W), P (over W ∪ E) and a chain T_1 ⊆ … ⊆ T_k (over W ∪ E ∪ Y), with radii rho_j and reach tolerance eta. The construction: A2 := V, G2 := ¬P ∪ T_{j*}, A1 := ∃_{E∪Y} A, R := ∀_{E∪Y}(¬A ∪ ¬A2 ∪ ¬G2 ∪ G), G1 := A2 ∩ R, Bad := A1 ∩ ¬∃_W G1. Conditions: D1 is A ⊆ A1, D2 is G1 ⊆ A2, D3+ is A ∩ G1 ∩ A2 ∩ G2 ⊆ G. I also use D2w for the weaker condition A ∩ G1 ⊆ A2 (the second side condition of `rule_general` in lean/Contracts.lean), and G1x := ∀_{E∪Y}(¬A ∪ ¬M2 ∪ G), the exact planner guarantee with the controller code inlined. Saturation of (A, G) is (A, G ∪ ¬A).

## 1. Soundness

### Finding 1.1 — F0, F1, F2. Verdict: CONFIRMED (with one unstated structural fact).
F0: if S is over Z then S is a union of classes of (Pi∖Z)-equivalence, so ¬S, S ∩ S', S ∪ S' are unions of such classes; classes of (Pi∖Z')-equivalence are finer when Z' ⊇ Z. F1 is immediate. F2 uses ∃_X ∃_{X'} = ∃_{X ∪ X'}, which holds because Omega is a product over ports: given σ, σ' that agree outside X ∪ X', the behaviour τ that copies σ' on X and σ elsewhere is X-equivalent to σ and X'-equivalent to σ'. Static ports are constant signals, but the space is still a product over ports, so this holds. Fix: say once that Omega is the product over ports of the per-port signal spaces; F2 depends on it.

### Finding 1.2 — F3 and F4, and the hypothesis "C over Pi∖X". Verdict: CONFIRMED.
F3, first half: if σ ∈ C and σ' is X-equivalent to σ with σ' ∉ S, then σ' ∈ ∃_X C = C ⊆ S, a contradiction; so C ⊆ ∀_X S. The converse is F1. Second half: σ ∈ ∃_X S is X-equivalent to some σ' ∈ S ⊆ C, so σ ∈ ∃_X C = C. F4: "⊆" since C = ∃_X C; "⊇" since if σ ∈ C is X-equivalent to σ' ∈ S then σ' ∈ C. The hypothesis is necessary: with X = {x}, C = S = {x = 0}, C ⊆ S but ∀_X S = ∅. Every use in the proof meets it: in (c), A and G are over Pi∖W; in (e), G1' is over U ∪ W = Pi∖(E ∪ Y); in (f), A1 is over U ⊆ Pi∖W; in "Why D3+", A2 ∩ G2 is over Pi∖U; in the remark on G2 and U, M2 ∩ A2 is over Pi∖U. Fix: none.

### Finding 1.3 — Theorem (a) and (b). Verdict: CONFIRMED.
(a) follows from F0 and F2 as written. (b): D1 is F1; D2 is by construction; D3+ because G1 ⊆ R ⊆ ¬(A ∩ A2 ∩ G2) ∪ G. Checked in Lean (`D1`, `D2`, `D3plus`). Fix: none.

### Finding 1.4 — Theorem (c), composition. Verdict: CONFIRMED, but GAP on non-vacuity.
The chain M ∩ A ⊆ M1 ∩ A1 ⊆ G1 ⊆ A2, then M2 ∩ A2 ⊆ G2, then D3+, is correct, and hiding W follows from F4 then F3. Lean: `compose`, `compose_hidden`, and `typed_meets_library` (the same result obtained from the library's `rule_general` and `rule_guarantee_tightening`). The gap is that M1 ∩ M2 ⊨ (A, G) holds trivially when the composite has no behaviour on part of A, for example when M2 rejects some valid mission or crashes on some environment input. Neither the setting nor the theorem asks for M2 to accept all inputs. Fix: add the hypothesis that M2 accepts every input, i.e. for every (w, e) with w ∈ V there is y with (w, e, y) ∈ M2, state that (f) gives the same for M1, and conclude that for every (u, e) ∈ A the composite has at least one behaviour, so that (c) says something.

### Finding 1.5 — Theorem (d), "which step 2 established". Verdict: GAP.
The set identity M2 ∩ V ⊆ ¬P ∪ T iff M2 ∩ V ∩ P ⊆ T is trivially true (Lean `obligation`). The claim that BMC establishes it hides four assumptions. (i) Number domains. Steps 3–5 quantify over real-valued ports, while the code reads IEEE doubles. The obligation is only checked for inputs that are doubles, and with V, P, T evaluated on those doubles. The clean repair is to declare that every port's domain is the doubles embedded in R, that atoms are evaluated exactly (as reals) on those values, and that the BMC encoding uses fp-to-real conversion for the atoms. Under that reading, steps 3–5 over all reals are conservative: R computed over R^n is contained in R computed over doubles, and A1 computed over R^n contains A1 computed over doubles, so D1 and (c) still hold. Maximality (e) and realizability (f) then hold for the real relaxation, not for the double semantics. (ii) NaN and infinite outputs: T must include "y is finite", otherwise the exact evaluation of the atoms is undefined. (iii) Initial internal state. M2 keeps state across ticks (S-curve state, previous target, the vehicle's velocity when the mission starts). As a set of port behaviours, M2 is the projection of its runs from the initial states allowed. A BMC run from one fixed initial state certifies only that state. Either the initial state is fixed by A (and that has to be said) or it is a port in E_s, constrained by P, and quantified in step 2. In the source this is concrete: the first leg starts at the stopping point, computed from the position and velocity estimates at initialisation (ardupilot/libraries/AC_WPNav/AC_WPNav.cpp, `wp_and_spline_init_m`, lines 252–255), not at the measured position. So the "start" p0 of the tube must be defined as that stopping point, or A must bound the initial speed so that the two differ by at most a stated margin. (iv) Fidelity of the encoding: the compiler model, undefined behaviour and library calls. This is standard but should be named as a trusted base. Fix: add a sentence fixing the double semantics and evaluating atoms exactly; put the initial state into E_s (or into A explicitly); require T to imply finite outputs; list the encoding as trusted.

### Finding 1.6 — Theorem (e), maximality and the chain. Verdict: CONFIRMED; the step 5 repair sentence is WRONG.
First part: A ∩ G1' ∩ A2 ∩ G2 ⊆ G iff G1' ⊆ ¬(A ∩ A2 ∩ G2) ∪ G iff G1' ⊆ R (F3). Second part: R is antitone in T, so among certified tubes the least one gives the largest G1 and the smallest Bad (Lean `maximal`, `R_antitone`, `chain_G1`, `chain_Bad`, `certified_upset`). Two remarks. (1) Maximality is relative to the strict D2. Under D2w, the largest admissible guarantee is G1 ∪ ¬A1, which has the same implementations (Lean `maximal_weak`), so nothing is lost; but the write-up should say that G1 is unsaturated and that its saturation is the maximum under D2w. (2) Step 5 says "A further repair needs a thinner tube than any certified one". This is false. A guarantee G2' that is not comparable with T_{j*} can give a strictly smaller Bad without being thinner anywhere that matters. Examples: a tube that is one-sided at corners (Finding 4.2), a narrower V that allows a thinner certified tube, or a P that takes over more of A. (e) only compares members of one fixed chain. Fix: replace the sentence with "within this chain no certified member gives a smaller Bad; a smaller Bad needs a guarantee outside the chain (a different shape, a smaller V or a larger P) or the code inlined".

### Finding 1.7 — Theorem (f), realizability. Verdict: CONFIRMED (one trivial hypothesis).
The construction M1 := G1 ∪ ¬A1 and the converse via F4 are correct. In typed form a total planner needs the mission domain to be nonempty (otherwise no output exists for u ∉ A1). Lean `realizable` proves the equivalence with a total relation, and `realizable_function` proves it with a function; both assume `Nonempty W`. A semialgebraic choice function exists by definable choice in o-minimal expansions of the real field (van den Dries 1998, Tame Topology and o-minimal Structures, Cambridge University Press), which supports the author's attack log, item A15. Fix: none needed in the two pages.

### Finding 1.8 — the "Hence" paragraph after the Theorem. Verdict: GAP (true but vacuous).
G1 contains V × ¬A1: for u ∉ A1, A(u, ·) is empty, so R holds at every w (Lean `G1_contains_vacuous_part`). In the worked example G1 = V ∧ (s ≤ 0 ∨ …), so "G1 ≠ ∅" holds whenever V ≠ ∅ and some s ≤ 0 is representable. The second equivalence (in V ∩ ∀_{E∪Y}(¬A ∪ ¬G2 ∪ G)) and the reading "A ⊆ P and A ∩ T ⊆ G at (u, w)" are both correct, and both are satisfied vacuously at u ∉ A1. Fix: state the test as A1 ∩ G1 ≠ ∅ ("some input allowed by A has a serving mission"), and point to Bad = ∅ as the test that matters.

### Finding 1.9 — "Why D3+ and not A ∩ A2 ∩ G2 ⊆ G". Verdict: CONFIRMED in substance; one overstatement and one missing link.
The equivalence with A2 ∩ G2 ⊆ ∀_U(¬A ∪ G) is F3, and D3+ is implied by both stronger forms (Lean `literal_D3_uniform`). Overstatement: "this pins the target to the origin" concerns only the fence conjunct. With the goal g also in U and unconstrained by A, ∀_U(¬A ∪ G) holds at no behaviour whose tick lengths A allows. So the short form forces A2 ∩ G2 to avoid A's tick-length range altogether, and for an M2 that accepts all inputs it forces V = ∅. Missing link: the second half (P cannot stay in A2) is an artefact of the strict D2. Under D2w (A ∩ G1 ⊆ A2), A2 := V ∩ P is admissible as long as A implies P at the relevant (u, w). Keeping P in the assumption (A2' := V ∩ P, G2' := T) under D2w gives the largest planner guarantee G1alt := ∀_{E∪Y}(¬A ∪ (V ∩ P ∩ (¬T ∪ G))). On A1, G1alt ⊆ G1 always (Lean `G1alt_sub`). The two are equal when every (u, e) allowed by A admits some target outside G (Lean `G1_sub_alt`). Otherwise the write-up's G1 is larger: at an environment outside P it accepts the mission if G happens to hold for every target. So moving P into G2 is at least as good as D2w with P kept, and equal in the case the write-up's own "Hence" paragraph assumes (Lean `strictD2_P`, `maximal_weak`). Fix: replace "pins the target to the origin" with "is empty on A's tick-length range, so for a controller that accepts every input it forces V = ∅"; add "with the weaker side condition A ∩ G1 ⊆ A2 of the guarantee-keeping sequential rule, P could stay in A2; moving it into G2 gives the same planner guarantee when every allowed (u, e) admits a target outside G, and a larger one otherwise".

### Finding 1.10 — the pointwise lemma. Verdict: CONFIRMED with corrected side conditions; GAP on its scope.
Precise statement. Fix the static values (U, W, E_s); let Z be the set of one tick's values of E_d ∪ Y; let α, γ_1, …, γ_m, c, d ⊆ Z (they may depend on the static values); a signal is z : {0,…,H} → Z; φ(z) means z_t ∈ α for all t and, for each j ≤ m, z_t ∈ γ_j for some t. Then:
- (Box) if H ≥ m: [for all z, φ(z) implies z_t ∈ c for all t] iff α = ∅, or α ∩ γ_j = ∅ for some j ∈ {1,…,m}, or α ⊆ c.
- (Diamond) if H + 1 ≥ m: [for all z, φ(z) implies z_t ∈ d for some t] iff α ⊆ d, or α ∩ γ_j ⊆ d for some j ∈ {1,…,m}.
- The static conjunct β of φ and a static conjunct β_G of G add the disjunct ¬β and, for β_G, the condition "¬β, or φ unsatisfiable, or β_G", where φ is satisfiable iff α ∩ γ_j ≠ ∅ for all j and α ≠ ∅ (needs H + 1 ≥ m).

Proof of the hard directions. Box: pick x_j ∈ α ∩ γ_j for j ≤ m and x* ∈ α ∖ c, put x_j on tick j − 1 and x* on every tick from m onward; this needs tick m to exist, i.e. H ≥ m. Diamond: pick x_j ∈ (α ∩ γ_j) ∖ d and x_0 ∈ α ∖ d, put x_j on tick j − 1 and x_0 on the remaining ticks; no tick lies in d, and only ticks 0,…,m − 1 are used, so H + 1 ≥ m suffices. Lean `box_iff`, `dia_iff`. The witnesses can always go on distinct ticks once there are enough ticks. Overlap among the γ_j only means fewer ticks would do, never more, so the author's concern about overlapping γ_j is unfounded. The bound H ≥ m is tight for the Box part: with H = 0, m = 1, α = Z = {true, false}, γ_1 = c = {true}, the implication holds over all signals but the pointwise condition fails (Lean `box_needs_H_ge_m`). For the Diamond part the write-up's H ≥ m is one more than needed. The m in "H ≥ m" must be the number of Diamonds in the antecedent after the split. That is m_A + m_T for A ∧ T, and m_A + 1 for A ∧ ¬P when ¬P contributes a Diamond (the negation of a Box conjunct of P); it is not the m of any single formula.
Scope (GAP). Φ requires every window to be [0, H]. A deadline shorter than the horizon, which is what the deadline-conversion sentence produces, leaves Φ. Applying the lemma's formula anyway is unsound. Take H = 1, α = ⊤, γ = d = {true}, with the antecedent's Diamond over ticks 0..1 and the consequent's deadline at tick 0. The condition α ∩ γ ⊆ d holds, yet the signal (false, true) meets the antecedent and misses the deadline (Lean `dia_window_mismatch`). In the example this is exactly the case of T's reach window [0, H] against a goal deadline shorter than H. Simplest correct extension (one Diamond each side, Box over [0, H]): let the antecedent's Diamond γ have window [0, D1] and the consequent's Diamond d have window [0, D2]. If D1 ≤ D2, the Φ formula is unchanged (α ⊆ d, or α ∩ γ ⊆ d, the latter covering α ∩ γ = ∅). If D1 > D2, the witness can sit at tick D1, outside d's window, and the condition becomes α ⊆ d or α ∩ γ = ∅. So for T's reach part to discharge a goal deadline, T must itself reach by that deadline. (Lean `dia_short_deadline`.) The lemma does extend to piecewise windows (split the ticks at window endpoints; the condition becomes per segment and needs enough ticks per segment), but that is not what is stated. The lemma also relies on E_d and Y being free across ticks inside R, which is true because G2 forgets the dynamics of M2. It fails if A couples ticks (a plant model), which is the "A mentions Y" case of Finding 1.15. A positive consequence the write-up misses: by the lemma, the author's two-tick Z3 instance checks (H = 1 ≥ m = 1) are complete for this class, not just samples.
Fix: state the lemma as above, with H ≥ m for Box and H + 1 ≥ m for Diamond, m counted after splitting; add "all windows equal [0, H]" to Φ and say what happens to deadlines.

### Finding 1.11 — the deadline-to-ticks conversion. Verdict: WRONG as a general rule; CONFIRMED for one polarity.
Let τ_t be the time elapsed at tick t (the sum of the first t tick lengths), with dt_min ≤ dt ≤ dt_max (dt_max is the write-up's overline dt). If tick t satisfies t · dt_max ≤ D, then τ_t ≤ D. So replacing a Diamond with deadline D in G by the tick window [0, ⌊D/dt_max⌋] strengthens G and is sound (Lean `deadline_dia_sound`). For a Box over the first D seconds in G, every tick with τ_t ≤ D satisfies t · dt_min ≤ D, so the sound window is [0, ⌊D/dt_min⌋] (Lean `deadline_box_sound`). The dt_max window is unsound for Box (Lean `deadline_box_dmax_unsound`: with constant tick length 1, dt_max = 2 and D = 2, tick 2 is inside the deadline but outside the window). Inside A the polarities flip, because strengthening an assumption weakens the contract: a Diamond with a deadline in A must use dt_min, and a Box in A must use dt_max. Fix: "Each timed operator is replaced by a tick window that makes G stronger and A weaker: Diamond windows in G and Box windows in A use ⌊D/dt_max⌋; Box windows in G and Diamond windows in A use ⌊D/dt_min⌋; the loss is governed by dt_max/dt_min." Combined with Finding 1.10, a converted deadline window shorter than H also leaves Φ.

### Finding 1.12 — "a guarantee for M2 that mentioned U would gain nothing". Verdict: CONFIRMED (and slightly stronger).
M2 ∩ A2 is over Pi∖U, so M2 ∩ A2 ⊆ G2' iff M2 ∩ A2 ⊆ ∀_U G2' (Lean `G2_with_U`). Since R is antitone in G2, replacing G2' by ∀_U G2' can only enlarge G1, so a U-dependent guarantee is never better and can be worse. The remark needs M2 to be over Pi∖U. If the real controller also reads part of U (for example home or a fence that the autopilot enforces itself), the remark fails and those ports must be moved to a shared input. Fix: add "provided M2 does not read U".

### Finding 1.13 — static vs per-tick ports, and the length field of W. Verdict: GAP (minor).
The Theorem is set-level and does not care which ports are static. Static U and W matter only for the pointwise lemma and for the claim that the output of QE is a PolySTL formula read at tick 0; both are right. The length field n is discrete. The formulas that mention "the last waypoint" or "the polyline through the waypoints" are case splits over n ∈ {1, …, N}, with slots after n left unconstrained, and n = 0 must be excluded by V. This costs O(N^2) atoms for the tube and should be said. If M2 reads only a prefix of the mission (for example it stops at the first item it cannot handle), then T (which talks about the whole list) fails in step 2. That is a completeness failure, not a soundness one, provided V excludes such items. Fix: one sentence on the encoding of n and on V excluding n = 0 and unreadable items.

### Finding 1.14 — horizon of T vs horizon of G, and mission length. Verdict: CONFIRMED; GAP in the worked example.
Certifying T on [0, H] with the H of A and G is necessary and sufficient for the construction. The reach conjunct of T can be certified only if every mission in V finishes within H ticks for every tick length P allows. With P's dt range [1/2000, 1/50] (the code's own range), H = 1.2·10^4 ticks covers as little as 6 s of travel. At a cruise speed v that is 6v metres, while V allows two legs of up to 100 m each. So, as stated, step 2 would not certify the reach part of the example's T. Section 5 already says P should take over A's dt range; the worked example does not. Fix: in the example put A's range Box(0.0024 ≤ dt ≤ 0.0026) into P, and add to V a bound on the total length ℓ_1 + ℓ_2 ≤ v · H · 0.0024 minus the acceleration allowance; or say that the example assumes this.

### Finding 1.15 — A mentioning Y; nondeterministic M2. Verdict: CONFIRMED with a caveat.
No proof step uses that A avoids Y: A1 := ∃_{E∪Y} A and R := ∀_{E∪Y}(…) are unchanged, and composition goes through (Lean `compose_A_with_Y`). Two caveats. First, an A that relates Y to E can be falsified by the controller's own outputs, which makes (A, G) easier to meet in a way the designer may not intend. Second, an A that couples ticks (a plant model x_{t+1} = f(x_t, y_t)) leaves Φ and also PolySTL's one-tick atoms. Nondeterministic M2: nothing uses determinism. The universal quantifier over Y in R is what handles nondeterminism, and replacing it with an existential would be unsound (author's attack log, item A8, correct). Fix: one sentence each.

### Finding 1.16 — step 1 and "every step is deterministic". Verdict: GAP.
Step 1 (reading V, P and the chain from guards and clamps) is not specified as an algorithm. Its output is a judgement call, and nothing guarantees that V and P capture the code's real input conditions. Soundness does not depend on step 1, because step 2 checks whatever step 1 proposes. But "Input: the code of M2" and "every step is deterministic" overstate. Also, binary search is correct only if every BMC call returns a definite answer. With timeouts treated as "not verified", soundness survives, but the result may not be the least certified index, and the second part of (e) then fails. Fix: call step 1 a proposal step whose output is trusted for nothing; state that BMC calls must be complete, or weaken (e) to "the least index whose check returned".

### Finding 1.17 — complexity sentence in Section 5. Verdict: GAP (loose, and miscounts variables).
"Doubly exponential in (H+1)(|E_d|+|Y|)" is the bound for cylindrical algebraic decomposition (Collins 1975, Automata Theory and Formal Languages, LNCS 33). It counts neither |E_s| nor the free variables of U ∪ W, which CAD's bound also depends on. R has one block of universal quantifiers. For a fixed number of quantifier blocks, the algorithm of Basu, Pollack and Roy (J. ACM 43(6), 1996) runs in time singly exponential in the number of variables of each block. The doubly exponential lower bound (Davenport and Heintz, J. Symbolic Computation 5, 1988) needs growing alternation. Fix: "one universal block over (H+1)(|E_d|+|Y|)+|E_s| variables with |U|+|W| free variables: singly exponential in the number of eliminated variables for a fixed number of free variables (Basu–Pollack–Roy), doubly exponential with CAD."

### Finding 1.18 — the worked example, parts (i)–(iv), the instance and Bad. Verdict: CONFIRMED (apart from Finding 1.14).
(i): A's dt range lies inside P's, so the α ∩ γ_1 of that branch is empty. (ii): the minimum and maximum of ‖w1 − p0‖ over the disc ‖p0 − h‖ ≤ δ are ‖w1 − h‖ − δ and ‖w1 − h‖ + δ, giving (ℓ_min + δ)^2 ≤ ‖w1 − h‖^2 ≤ (ℓ_max − δ)^2. (iii): the ρ-neighbourhood of a segment lies inside the square F_s iff both endpoints lie inside F_{s−ρ}, and the start disc lies inside F_{s−ρ} iff ‖h‖_∞ ≤ s − ρ − δ. (iv): α ∩ γ_1 is the η-disc at w2 (inside the tube because η ≤ ρ), which lies inside the ε-disc at g iff ‖w2 − g‖ ≤ ε − η. Instance: legs √5000 ≈ 70.7; (−1.72, −50.02) is at distance 2.00 from w1 = (0, −49) and outside F_50; ‖w2 − g‖ = 4 > 2.5 for the third mission. Bad at s = 50: the midpoint witness needs ‖h − w2‖ ∈ [12, 198], and the box diagonal is 96√2 ≈ 135.8 < 198; the radius-20 witness gives a second leg in [8, 32]. Both are correct. Fix: only Finding 1.14.

### Finding 1.19 — "If U were per-tick, an output atom could couple two ticks". Verdict: CONFIRMED (the mechanism should be named).
With per-tick U, the per-tick values of E_d and Y are still free and independent across ticks, so by themselves they produce only one-tick conditions on u. The coupling comes from eliminating the static environment ports E_s, which are shared by all ticks. For instance, ∀p0 ∈ R. ⋁_t (v_t ≤ p0 ≤ u_t) says that the intervals [v_t, u_t] cover R; the result of eliminating p0 contains atoms such as u_1 ≥ v_2, which relate values at two ticks. PolySTL atoms read one tick, so such atoms are outside the logic, although nested future operators over a finite horizon can still express the ordering structure. Fix: replace "an output atom could couple two ticks" with "eliminating the static environment ports can produce atoms that relate values of U at different ticks".

### Finding 1.20 — decidability of step 2. Verdict: GAP.
"Real quantifier elimination if the code is read over the reals" needs the code to be semialgebraic: +, −, ×, ÷, comparisons, and square roots (which are definable). Waypoint-navigation code also calls atan2, sin, cos and similar functions. Read over the reals, these leave the decidable theory, and real arithmetic with sine is undecidable (Richardson, J. Symbolic Logic 33, 1968). Under the IEEE reading the question stays finite only if the library functions are replaced by their bit-level implementations, or by sound semialgebraic enclosures (which can only make certification harder). Fix: say which reading is used, and that transcendental library calls are either modelled bit-precisely or enclosed. Also say that the horizon of 1.2·10^4 ticks makes bit-precise BMC of floating-point code extremely large. Certifying the Box part of T by an inductive invariant (a one-tick check, or k-induction) and the reach part by a progress measure (distance along the polyline decreasing by at least v_min · dt_min per tick) would make step 2 independent of H.

### Finding 1.21 — the reach conjunct of T is a closed-loop property, but P is over W ∪ E. Verdict: GAP (significant).
In the controller source (ardupilot/libraries/AC_WPNav/AC_WPNav.cpp, `advance_wp_target_along_track`, lines 583–590), the progress clock is scaled by a factor clamped to [0, 1]. The factor is 0.05 + (along-track speed estimate − kP · along-track position error) / ‖target velocity‖, and the position error is target minus estimate. A non-fast waypoint also counts as reached only when the position estimate is within the waypoint radius (lines 640–650). With the per-tick estimates in E_d free, as step 2 treats them, the raw factor can be 0 on every tick. The filtered progress rate then decays geometrically (filter step dt divided by the jerk time constant), so the total progress along the leg is bounded, and a non-fast leg never hands over. So "some tick brings the target within η of the last waypoint" is false for some admissible environment, and the reach part of every T_j fails in step 2, whatever ρ_j is. The Box (tube) part is unaffected: the scaled clock changes the speed along the path, not the path (project file notes/ardupilot/controller-ports.md, section on time scaling). Certifying reach needs an environment condition that bounds the tracking error, such as ‖estimate_t − y_t‖ ≤ L_p and a matching bound on the velocity error. That condition relates E_d to Y, so it cannot be put into P as typed (P over W ∪ E). And for the ¬P branch of R to be vacuous, A must then mention Y too. The theory survives this. The set-level proofs allow P over W ∪ E ∪ Y and A over U ∪ E ∪ Y (Finding 1.15), and one-tick tracking bounds stay in Φ. But the write-up's typing of P and A, its claim that the controller check is open-loop, and the worked example all have to change. The top-level A then contains a plant assumption that the controller's own targets can break, if they are not dynamically trackable. Fix: type P over W ∪ E ∪ Y. ## 2. Relation to known constructions

### Finding 2.1 — G1 is the AG quotient restricted to the planner's alphabet. Verdict: CONFIRMED (the construction is known).
Incer, Sangiovanni-Vincentelli, Lin and Kang (MEMOCODE 2018, "Quotient for assume-guarantee contracts") give the saturated quotient (A, G)/(A2, G2) = (A ∩ G2^s, (A2 ∩ G) ∪ ¬(A ∩ G2^s)) with G2^s := G2 ∪ ¬A2. The same closed form is recovered in the hypercontract framework of Incer, Benveniste, Sangiovanni-Vincentelli and Seshia (NFM 2022, "Hypercontracts") and in the preorder setting of Íncer Romeo, Mangeruca, Villa and Sangiovanni-Vincentelli (GandALF 2020, "The quotient in preorder theories"). The Benveniste et al. monograph (Foundations and Trends in Electronic Design Automation 12(2–3), 2018), Section VII-A, still says that no quotient is known for assume–guarantee contracts. Its quotient is developed for modal interfaces, and Algorithm 1 of its Section VIII-E decomposes C into C restricted to a sub-alphabet, composed with the quotient of C by that restriction.

The identity. A component M over Pi implements the quotient iff M ⊆ ¬A ∪ (A2 ∩ (¬G2 ∪ G)). If M is over U ∪ W, F3 turns this into M ⊆ ∀_{E∪Y}(¬A ∪ (A2 ∩ (¬G2 ∪ G))). Pointwise in (u, w), that set equals ¬A1 ∪ G1: if w ∈ A2, both sides reduce to ∀_{E∪Y}(¬A ∪ ¬G2 ∪ G) (at u ∉ A1 both are true); if w ∉ A2, both reduce to ¬A1. Hence:

  a planner over U ∪ W implements (A1, G1) iff it implements (A, G)/(A2, G2).

Lean: `planner_iff_quotient` and `saturated_G1` (both need a nonempty Y; otherwise the universal quantifier over Y is vacuous). So (A1, G1) is, up to saturation, the largest contract over the alphabet U ∪ W that refines the quotient. In the monograph's vocabulary that is the refined projection of the quotient onto U ∪ W. The order of operations is the reverse of Algorithm 1. There, the first sub-contract is a restriction of C, and the quotient carries the rest. Here, the controller's contract comes from the code (steps 1–2), the quotient is formed by it, and the quotient is then projected universally onto the planner's ports. The closest match is Pacti (Incer, Badithela, Graebener, Mallozzi, Pandey, Yu, Benveniste, Caillaud, Murray, Sangiovanni-Vincentelli, Seshia; arXiv:2303.17751, 2023; ACM TCPS 2025). I checked its text. Its quotient formula is the one above. Its procedure ContractQuotient for input–output contracts types the missing component with inputs I^q = (O' ∖ O) ∪ (I ∖ I') and outputs O^q = (O ∖ O') ∪ (I' ∖ I), and it removes every other variable from the quotient's assumption and guarantee by context-aided variable elimination (Incer, Benveniste, Murray, Sangiovanni-Vincentelli, Seshia, "Algorithms for context-aided variable elimination", UC Berkeley EECS technical report UCB/EECS-2023-15, 2023). The output is a refinement of the quotient. For the present ports the top level has I = U ∪ E and O = Y, and the controller has I' = W ∪ E and O' = Y. This gives I^q = U and O^q = W, which is exactly the typing of (A1, G1). So the write-up's steps 3–4 are Pacti's input–output quotient for this architecture, with two differences. Variables are eliminated exactly, by real quantifier elimination, instead of by a polyhedral refinement. And the formulas are temporal (PolySTL) instead of static linear constraints, which is where the pointwise lemma is needed. Pacti's autonomy case study also has the same two-step shape: a controller contract is fitted first, then the system contract is divided by it.

### Finding 2.2 — G1 is the weakest assumption of the most permissive implementation of (A2, G2). Verdict: CONFIRMED (known).
Giannakopoulou, Păsăreanu and Barringer (ASE 2002, "Assumption generation for software component verification") define the weakest assumption of a component M for a property φ over the interface alphabet Σ = (alphabet(M) ∪ alphabet(φ)) ∩ alphabet(environment). Here M = M2, φ = (A → G), and the environment of M2 is the planner, so Σ = U ∪ W. In set form the weakest assumption is exactly G1x = ∀_{E∪Y}(¬A ∪ ¬M2 ∪ G). Lean `exact_iff`: M1 ∩ M2 ⊨ (A, G) iff M1 ⊆ G1x. If the code M2 is replaced by its most permissive implementation of (A2, G2), namely ¬A2 ∪ G2, the same expression gives ∀_{E∪Y}(¬A ∪ (A2 ∩ (¬G2 ∪ G))) = ¬A1 ∪ G1. Inlining the code instead (P := ⊤, T := M2) gives G1 = V ∩ G1x (Lean `G1_inlined`). The L*-based learners compute or approach G1x by membership queries that run M2: Cobleigh, Giannakopoulou and Păsăreanu (TACAS 2003, "Learning assumptions for compositional verification"), and Alur, Madhusudan and Nam (CAV 2005, "Symbolic compositional verification by learning assumptions"), who do it with BDDs inside NuSMV. The write-up does the opposite: it never consults M2 while computing G1, and pays with the loss of Section 4. The closest classical relative of "abstract M2 first, then compute the assumption from the abstraction" is the abstraction-refinement approach of Gheorghiu Bobaru, Păsăreanu and Giannakopoulou (CAV 2008, "Automated assume-guarantee reasoning by abstraction refinement"), which refines by counterexamples. The chain of tubes is a fixed, one-parameter family refined without counterexamples.

### Finding 2.3 — D3+ and `rule_general`. Verdict: CONFIRMED.
`rule_general` gives M1 ⊗ M2 ⊨ (A, G1 ∩ G2) from A ⊆ A1 (D1) and A ∩ G1 ⊆ A2 (D2w, implied by D2). Guarantee Tightening then needs (G1 ∩ G2) ∩ A ⊆ G. Under D2w, (G1 ∩ G2) ∩ A = A ∩ G1 ∩ A2 ∩ G2, so the tightening side condition is equivalent to D3+ (Lean `D3plus_iff_tightening`, `delegation_D3plus`). So D1, D2w and D3+ are exactly the side conditions left after the two implementation premises (the M-terms) are dropped from "rule_general followed by tightening". The library's own `delegation` theorem uses G2 ∩ A2 ⊆ G instead, which is the uniform condition shown unusable in Finding 1.9. The write-up should therefore present its D3+ as the library's `rule_general` plus tightening, not as a new rule, and note that its D2 is stronger than what that rule needs.

### Finding 2.4 — what is new and what is not.
Not new:
1. The planner contract: it is the AG quotient by the controller's contract, projected universally onto the planner's ports (Finding 2.1). Equivalently, it is the weakest assumption of the controller's most permissive implementation (Finding 2.2).
2. Maximality (e): it is the adjunction property of the quotient plus F3.
3. Realizability (f): it is the ∀u ∃w reading of that projection.
4. Composition with a hidden wire: it is the hiding rule, already in lean/Hiding.lean.
5. "Unsaturated contracts with W in neither A nor G": unsaturated and saturated contracts have the same implementations, and a top-level contract that does not mention internal wires is the normal case for hiding.
6. Binary search on a chain of candidate guarantees: candidate filtering against a verifier is the Houdini idea of Flanagan and Leino (FME 2001, "Houdini, an annotation assistant for ESC/Java").
7. A code-derived controller contract followed by a quotient: Pacti's case study.

8. Delegation as a contract quotient over STL: Damera, Matheu and Baras (arXiv:2610.33349, October 2026, "Contract-Based Agentic Systems Engineering: Delegation as Quotient for Assured System Design") compute the quotient of STL contracts over a common signal space. Their closure result is the Boolean substitution into the closed form, and they do not restrict the alphabet. Relative to that paper, what is new here is the universal projection onto the planner's ports, the pointwise lemma that makes it horizon-independent, and the certified controller contract.

What is new, honestly modest:
1. The pointwise lemma. It makes the ∀ projection over the free per-tick signals horizon-independent for the Φ class. It is elementary, and I did not find it stated in the contract literature the two surveys cover.
2. Pacti's input–output quotient carried out exactly, by real QE, for a temporal (PolySTL) contract, with the output a static semialgebraic set over (u, w). Pacti's elimination is a polyhedral refinement and its formulas are static.
3. The bookkeeping that keeps M2's obligation fixed while moving P from the assumption into the guarantee (needed only because D2 is strict).
4. The packaging of a code object (the chain plus one BMC campaign) as a guarantee whose size does not depend on the code.
5. A precise account of what is lost by not inlining (Section 4 below; the write-up has only one sentence on it).

Fix: the write-up should name the construction "the AG quotient by a code-certified controller contract, projected onto the planner's ports". It should cite Incer et al. 2018, Giannakopoulou et al. 2002 and Damera et al. 2026 next to the Theorem, and claim as contribution only items 1–5.

## 4. Conservatism

### Finding 4.1 — the exact gap as a set. Verdict: GAP in the write-up (stated in one sentence only); characterised here.
Let A1 be as above, and let G1x := ∀_{E∪Y}(¬A ∪ ¬M2 ∪ G) be the exact (inlined) planner guarantee. The accepted sets on the relevant inputs are

  Acc_exact := {(u, w) : u ∈ A1, (u, w) ∈ G1x},   Acc_G1 := {(u, w) : u ∈ A1, (u, w) ∈ G1}.

If M2 is certified, Acc_G1 ⊆ Acc_exact ∩ (U × V) (Lean `G1_sub_exact`). The loss Δ := Acc_exact ∖ Acc_G1 splits into three disjoint parts:
- Δ_V: missions outside V that the code handles correctly (legs shorter than ℓ_min, item kinds that V excludes);
- Δ_P: missions in V at inputs where A allows an environment outside P, for example ‖w1 − h‖ < ℓ_min + δ in the example, which the code may still handle;
- Δ_T: missions in V where every environment allowed by A satisfies P, and where some target sequence inside T breaks G but no sequence that M2 actually produces does.

Only Δ_T depends on ρ. For G in Φ, membership in G1x depends on M2 only through the set D(w, e) of target values visited by M2's run and through whether that run enters the Diamond sets. So Δ_T is the set of (u, w) where, for every e allowed by A, D(w, e) meets the conditions of G, but the tube T_ρ(w, e) does not.

### Finding 4.2 — a formula for the fence part, and why the gap does not vanish. Verdict: the write-up's implicit expectation ("repair needs a thinner tube") is WRONG.
Take a convex polygonal fence with facets n_i · z ≤ b_i (unit normals n_i), and write σ_S(n) := sup{n · z : z ∈ S} for the support function of a set S. The exact quotient needs σ_D(n_i) ≤ b_i for every facet; G1 needs σ_{T_ρ}(n_i) ≤ b_i. For a ρ-tube around a polyline with vertices v (the start, the waypoints), σ_{T_ρ}(n) = max_v n · v + ρ. Let ρ_min be the true deviation of the controller (the supremum over valid inputs of the distance from D to the polyline). Then D lies inside the ρ_min-tube, so σ_D(n) ≤ max_v n · v + ρ_min. Also σ_D(n) ≥ n · v* − dist(v*, D), where v* is the maximising vertex. So the facet-i margin lost by G1 is

  Δ_i(w, e) := σ_{T_ρ}(n_i) − σ_D(n_i) ∈ [ρ − ρ_min, ρ + dist(v*, D)].

In (u, w)-space, Δ_T for the fence is the union over facets of the strips {b_i − Δ_i < σ_D(n_i) ≤ b_i}, of width Δ_i. For missions spread uniformly over the fence, the lost fraction is roughly 2 · (number of constrained vertices) · Δ / (fence half-width). As ρ → ρ_min, the lower bound goes to 0 but the upper bound goes to ρ_min + dist(v*, D) > 0. The gap vanishes only if, at every maximising vertex and in every facet direction, the controller actually deviates outward by the full ρ_min. A controller that cuts corners inward does the opposite. Numerical check (scratch script, two legs with an inward circular blend of length L at the lowest vertex): ρ_min = 0.3L, inward cut in the facet direction 0.5L, so G1 at ρ = ρ_min still loses Δ = 0.8L ≈ 2.7 ρ_min (L = 1, 2, 4, 8 m give Δ = 0.8, 1.6, 3.2, 6.4 m). The example's rejected mission ((0, −49), (40, 40)) at s = 50, h = (−40, −40) is an instance. In a second scratch run, a toy controller blends the corner at w1 with an inward arc of blend length L ∈ {0.5, 1, 2, 3} m, and 73 starts on the circle ‖p0 − h‖ = 1 are tried. The largest ‖target‖_∞ is 48.91, 48.83, 48.66 and 48.49 m, inside F_50 in every case, so the exact quotient accepts the mission while G1 (ρ = 2) rejects it. The toy's measured deviation is 0.14 to 0.83 m. A ρ_min-tube would accept this mission (49 ≤ 50 − ρ_min), so here thinning would help. Even so, at L = 3 the ρ_min-tube reaches ‖·‖_∞ = 49 + 0.83 = 49.83 while the real targets stay within 48.49. The residual Δ at ρ = ρ_min is 1.34 m = ρ_min + 0.51 m of corner cut, a shape effect that no thinner isotropic tube removes. The goal part loses η − η', where η' ≤ η is the true reach accuracy, which goes to zero only if η is made tight. Δ_V and Δ_P do not depend on ρ at all.
What breaks if the gap does not go to zero: soundness does not break. Completeness does: Bad then over-approximates the inputs that no mission can serve with the real controller. Goals or homes within ρ + η of the fence are reported Bad although the code would serve them. The claim "Bad is exactly the set of inputs that no mission serves" is true only "under this controller guarantee", which the write-up does say. The repair sentence of step 5 is false (Finding 1.6).
Code evidence for the shape gap. The project's own analysis of the corner (notes/ardupilot/controller-ports.md, part (ii) of the corner section) writes the blended target as W − r·u1 + s·u2, with W the waypoint, u1 and u2 the unit leg directions, r ≥ 0 the distance left on leg 1 and s ≥ 0 the distance covered on leg 2. Writing L1 and L2 for the leg lengths, this point equals the convex combination (1 − r/L1 − s/L2)·W + (r/L1)·(W − L1·u1) + (s/L2)·(W + L2·u2) whenever r/L1 + s/L2 ≤ 1. So the target lies in the triangle conv(w_{i−1}, w_i, w_{i+1}), on the inner side of the corner, and its support function never exceeds max_v n·v plus the half-tick admission error. The isotropic tube of radius WP_RADIUS_M (2 m by default) therefore gives away about 2 m of fence margin at every outer vertex. The triangle-shaped guarantee below recovers that margin, provided step 2 also certifies r/L1 + s/L2 ≤ 1 (or V bounds the leg lengths against the turn angle so that it holds).
Fix: (1) add the decomposition Δ = Δ_V ∪ Δ_P ∪ Δ_T and the support-function bound to the Theorem's discussion. (2) Replace the isotropic chain with a chain of shape-aware guarantees. One candidate: "target within ρ'_j of the union of triangles conv(w_{i−1}, w_i, w_{i+1})". Its support function equals max_v n · v + ρ'_j, so the fence condition keeps its form, but ρ'_j needs to cover only the along-track overshoot, not the corner cut. (3) Report the Bad of the thinnest uncertified member next to the certified one, as a measure of how much the chain loses. In the worked example at s = 50, with ρ' = η = 0.5 and taking the goal along a coordinate axis for simplicity: the goal part of Bad moves from ‖g‖_∞ > 50.5 (isotropic tube, ρ = 2) to ‖g‖_∞ > 52 (triangle guarantee). For a controller that reaches w2 exactly and stays inside the fence the threshold is 53. The home part moves from ‖h‖_∞ > 47 to ‖h‖_∞ > 48.5, against 49 for the start disc alone.

### Finding 5.2 — break-even. Verdict: stated here.
Let k be the chain length, n2 := ⌈log2 k⌉ + 1 the number of controller BMC calls per controller configuration, and σ the number of distinct controller configurations (distinct horizons and P) among the Q queries, 1 ≤ σ ≤ Q. Costs: c2 for one controller BMC, cq for steps 3–5 for one query (about zero by hand in Φ, possibly huge outside Φ), c1 for one planner check against G1, cM for one monolithic BMC of planner plus controller for one query. R is the number of planner revisions. Then

  C_deleg = σ · n2 · c2 + Q · cq + R · Q · c1,   C_mono = R · Q · cM,

and delegation is cheaper iff

  σ · (⌈log2 k⌉ + 1) · c2 + Q · cq < R · Q · (cM − c1).

With one configuration (σ = 1), this reads R · Q > ((⌈log2 k⌉ + 1) · c2 + Q · cq) / (cM − c1). If cM is about c2 and c1, cq are much smaller, delegation wins once R · Q > ⌈log2 k⌉ + 1. Delegation is slower:
- for a single revision and a single query (R = Q = 1) whenever (⌈log2 k⌉ + 1) · c2 + cq + c1 ≥ cM, which holds for k ≥ 2 if cM ≤ c2 (item 7 above);
- whenever σ is close to Q (query-dependent horizons or P) and R is small;
- outside Φ, where cq dominates;
- whenever the monolithic check is incremental across revisions, which shrinks its per-revision cost.

A cheaper middle route that the write-up does not consider: skip QE entirely and check each planner revision directly against the abstraction, with one existential query ∃ u, e, y with A ∧ V(M1(u)) ∧ G2 ∧ ¬G. That needs no M2 code and no Φ, at a cost between c1 and cM. Fix: replace "the delegation costs about one controller check…" with the inequality above and the list of assumptions, and present the abstraction check as the fallback outside Φ.
