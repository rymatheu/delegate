# Lean listings in LaTeX: JetBrains Mono with symbol fallback, VS Code-like colours

Tested locally with TeX Live 2025 (minted 3.6.0, latexminted 0.5.0, Pygments 2.19.1), XeLaTeX and LuaLaTeX,
JetBrains Mono 2.x, JuliaMono. Two routes share the same colours and the same lexer.

| | Live route (minted) | Static route (pre-highlighted) |
|---|---|---|
| Needs | `-shell-escape`, `~/.latexminted_config`, Python 3.12/3.13 | nothing at compile time |
| Overleaf | custom lexer very likely blocked (see below) | works |
| Code lives | in the `.tex` file | in a generated `.tex` fragment |
| Inline `\lean|...|` | yes | no (use `\texttt`) |

## Files
- `lean4vscode.py`: Pygments lexer. Extends Pygments' Lean 4 lexer so that the declared name after
  `theorem`/`def`/... is its own token class, round/square/curly brackets another, angle brackets another.
- `leancolors.tex`: the colours and `\leanapplycolors`, which sets the Pygments token macros. Shared by both routes.
- `leanstyle.tex`: live route. Hooks `\leanapplycolors` into minted 3's style loading; defines `leancode` and `\lean`.
- `prehighlight.py`: static route. Writes a fancyvrb `Verbatim` fragment for a file or one declaration, and the
  Pygments macro definitions (`leanpyg-defs.tex`).
- `delegation.tex`, `leanpyg-defs.tex`: generated by `prehighlight.py` from `lean/Contracts.lean`.
- `fallback-xe.tex`: XeLaTeX only. `\newunicodechar` lines for the characters JetBrains Mono lacks
  (∖ ⊨ ⪯ ⦃ ⦄ ⁻ ᵢ ⱼ ₐ ₑ ₒ ₓ ⋀ ⋁ ⟹ ⊚, checked against the font file), taking them from JuliaMono only while the
  monospace family is active, so text and math fonts are untouched.
- `preamble-lualatex.tex`, `preamble-xelatex.tex`: complete minimal documents for the live route.
- `body.tex`: example body for the live route. `latexminted_config.example`: contents for `~/.latexminted_config`.

## Fonts
`./fonts/jetbrainsmono/JetBrainsMono-{Regular,Bold,Italic,BoldItalic}.ttf` and
`./fonts/juliamono/JuliaMono-{Regular,Bold}.ttf` next to the main `.tex` file. Both fonts have a 0.600 em advance
and a 0.550 em x-height, so fallback glyphs sit on the same grid as JetBrains Mono. The fallback is attached only to
the monospace font (LuaLaTeX: `RawFeature={fallback=...}` on `\setmonofont`; XeLaTeX: `\leanfb` tests the current
family), so the roman, sans and math fonts are not affected.

LuaLaTeX (preferred: one line covers every missing glyph):

    \directlua{luaotfload.add_fallback("leanfallback", {"[./fonts/juliamono/JuliaMono-Regular.ttf]:mode=harf;"})}
    \setmonofont[Path=./fonts/jetbrainsmono/, Extension=.ttf, UprightFont=JetBrainsMono-Regular,
      BoldFont=JetBrainsMono-Bold, ItalicFont=JetBrainsMono-Italic, BoldItalicFont=JetBrainsMono-BoldItalic,
      RawFeature={fallback=leanfallback}]{JetBrainsMono}

XeLaTeX (no font fallback; characters listed explicitly):

    \setmonofont[...]{JetBrainsMono}
    \newfontfamily\leanfallbackfont[Path=./fonts/juliamono/, Extension=.ttf, UprightFont=JuliaMono-Regular,
      BoldFont=JuliaMono-Bold]{JuliaMono}
    \usepackage{newunicodechar}
    \input{fallback-xe}

## Static route (Overleaf)
Locally, once per change of the code:

    python3 prehighlight.py --style-defs leanpyg-defs.tex
    python3 prehighlight.py ../../lean/Contracts.lean --decl delegation --out delegation.tex

Upload `leanpyg-defs.tex`, `leancolors.tex`, `delegation.tex` and the fonts. Preamble:

    \usepackage{xcolor,fancyvrb}
    \input{leanpyg-defs}\input{leancolors}\leanapplycolors

and `\input{delegation}` where the listing goes. No minted, no shell escape, no Python on the server.

## Live route (minted 3)
1. `lean4vscode.py`, `leancolors.tex`, `leanstyle.tex` (and `fallback-xe.tex`) next to the main file.
2. minted 3 refuses custom lexers unless they are listed by SHA-256 in `~/.latexminted_config`
   (or `$TEXMFHOME/.latexminted_config`; a copy in the working directory is ignored by default):
       {"custom_lexers": {"lean4vscode.py": ["<sha256 of lean4vscode.py>"]}}
   Recompute with `shasum -a 256 lean4vscode.py` after any edit to the lexer.
3. Load minted with `highlightmode=immediate`; otherwise minted 3's default `fastfirst` mode shows `<MINTED>`
   placeholders on a cold cache until the second pass.
4. `lualatex -shell-escape main.tex` or `xelatex -shell-escape main.tex`.

On Overleaf the home directory is not yours, and latexminted ignores a project-level config unless a home or
TEXMFHOME config enables it, so the custom lexer is expected to be refused there (a report of exactly this:
github.com/tuetenk0pp/sharelatex-full/issues/71). Untested here: a root `latexmkrc` with
`$ENV{'TEXMFHOME'} = './texmf';` and the config in `./texmf/.latexminted_config` (latexminted reads TEXMFHOME
through kpsewhich). If that fails, use the stock lexer (`\newminted[leancode]{lean4}{...}`: colours still apply,
but declared names and brackets are not distinguished) or the static route.

## Known issue
latexminted 0.5.0 crashes under Python 3.14 (`ArgParser.__init__() got an unexpected keyword argument
'color'`), which shows up as "minted v3+ executable is not installed". Put a Python 3.12/3.13 first on PATH
when compiling, e.g. `PATH=~/miniconda3/bin:$PATH lualatex -shell-escape main.tex`.
